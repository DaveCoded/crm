# Evolu 8 browser sync spike

30 September 2026. Synthetic data only. The throwaway implementation and reproduction steps are on local branch `codex/evolu-feasibility-spike`, commit `d39c23e` (`SPIKE.md`). This result answers the browser/Vite+ portion of [DAV-10](https://linear.app/dave-bernhard/issue/DAV-10/spike-evolu-8-for-encrypted-local-first-sync); it does not choose the production sync stack.

| Gate                                  | Result                   | Evidence                                                                                                                                                                                                                                            |
| ------------------------------------- | ------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| TypeScript 7 and Vite+                | Pass                     | Upgraded the isolated worktree to TypeScript 7.0.2 and `exactOptionalPropertyTypes`. `vp check` and `vp run build` passed with `@evolu/common` 8.12.0 and `@evolu/web` 3.2.0.                                                                       |
| Browser local write and reload        | Pass                     | Headless Chrome inserted a synthetic person and reloaded it with the same owner secret. An immediate query after insert was stale; a later refresh returned the row. The product UI will need the documented query subscription pattern.            |
| Restore to a second browser profile   | Pass, narrow             | A fresh Chrome profile given the same synthetic mnemonic fetched the first profile's row through a local `@evolu/relay` 4.1.1 instance. The mnemonic was copied manually for this experiment.                                                       |
| Write offline, sync later             | Pass, narrow             | With the relay stopped, profile B wrote another row locally. After the relay restarted, profile A received it. This tested a local relay, not separate networks.                                                                                    |
| Relay content opacity                 | Supporting evidence only | Its SQLite database contained two `evolu_message` rows, and a raw byte scan found neither synthetic name. This is not a security audit or proof about all metadata.                                                                                 |
| Local data encryption at rest         | Unverified               | Browser persistence worked, but we have not audited local SQLite encryption or designed secure storage for the owner secret. The throwaway code intentionally uses `localStorage` for a synthetic mnemonic and must not be used with real contacts. |
| Tauri macOS/Android and notifications | Unverified               | No Android SDK was found in the usual locations on this Mac. A physical Android device check is still required for encrypted storage, offline edits, restore, and app-closed daily notifications.                                                   |
| Production recovery and relay         | Unverified               | Restore UX, backup retention, loss of both devices, network deployment, migration, purge, and concurrent same-field edits still need validation.                                                                                                    |

**Decision:** Continue evaluating Evolu. Its browser/Vite+ path is feasible, including local asynchronous sync. Keep E2EE, local encryption at rest, and recovery after losing both devices as release gates. Do not adopt Evolu or start recording real relationship data until those gates pass. If Evolu fails, evaluate Automerge Repo with Keyhive and then Yjs; a non-CRDT encrypted design is allowed. Classic Jazz is excluded.
