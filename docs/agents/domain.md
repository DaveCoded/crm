# Domain docs

Before work that uses project terminology, read root `GLOSSARY.md` when it exists. Before changing a design decision, read relevant ADRs in root `docs/adr/` when they exist. Their absence needs no setup work.

This is a single-context repo: one root glossary and one root ADR directory. Create the glossary only when a term is resolved, and an ADR only for a consequential, hard-to-reverse trade-off. Use glossary terms in specs and issues. Surface any conflict with an ADR before changing course.
